content/posts/  ← 毎日の記事を置く場所（ここにファイルを1つ置くだけで、サイトが自動で更新されます）

【ファイル名】 blog_post_YYYYMMDD.py   例: blog_post_20260924.py
【流れ】
  1. 記事ファイルを content/posts/ にアップロード（または GitHub 上で新規作成して貼り付け）
  2. GitHub Actions「Build site」が自動で動き、次のページが作り直されます（約1分）
       ・新しい記事ページ（前の記事へのリンク付き）／直前の記事ページ（「次の記事」リンクを追加）
       ・ブログ一覧・サイトマップ・トップの「最新の市況ブログ」
  3. Cloudflare が自動で公開（約1分）
【うまくいかないとき】 Actions の「Build site」→ 実行 → Summary に、日本語で原因が表示されます。
  検査に失敗した場合、公開中のサイトは一切変わりません（壊れません）。
【検査の内容】 必要な項目の不足／日付とファイル名の不一致／地の文が1,500字未満／存在しないページへのリンク／韓国語の混入／構造化データの形式／サイトマップの整合
【記事を消したいとき】 記事ファイルを削除 → Actions の「Build site」を手動実行し、prune にチェック
